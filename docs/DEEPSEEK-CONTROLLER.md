# DeepSeek 语音控制与后端协议

更新于 2026-11-26。

Dog1 将本地语音转写、当前场景状态和动作目录交给 DeepSeek。模型在一次请求里生成自然回应和动作计划，Unity 校验后执行。桌面文字输入和语音转写使用同一条自由语言入口。

## 请求

Windows 设置页可将 API Key 加密保存到本机。密钥使用当前 Windows 用户的 DPAPI 保护，按接口协议、域名和端口隔离，保存在用户数据目录的 `ModelCredentials` 中。重新进入 Play 或重开 Unity 会自动加载；`KEEP_A_DOG_API_KEY` 环境变量仍优先。测试存档隔离运行时不会读取本机保存的密钥。其他平台仍可填写本次运行的密钥。

官方接口缺少密钥时不发起请求。HTTP 401、403、429、服务故障和网络超时通过逐请求错误回调传回自然回复和执行链，保持空动作，不再显示为语音“没听清”。错误提示不包含密钥或服务端响应正文。

请求正文包含玩家原话 `utterance` 和 Unity 测量的 `state`。状态提供地点、饱腹、饮水、体力、心情、清洁程度、已学命名口令，以及主人、玩具、休息点和活动空间的可用信息。五项需求均为 0–100。

`state.actionCatalog` 当前包含 **29 个动作 ID 与目标的组合**。每项提供 `id`、`target`、`label`、`tags`、`available` 和不可用原因 `reason`。模型只能选择本次目录中可用的组合。目录随狗的姿态、需求、视线、道具位置和场景变化。

| 动作组 | ID 与目标 |
| --- | --- |
| 姿态、移动与表达，共 12 项 | `sit`、`crouch`、`spin`、`come`、`paw`、`bow`、`invite`、`pounce`、`burst`、`sniff`、`pet`、`refuse`，目标均为 `none` |
| 取物，共 2 项 | `fetch_toy`、`fetch_lollipop`，目标均为 `none` |
| 休息，共 3 项 | `rest` 分别对应 `none`、`house`、`cushion` |
| 看向主人，共 3 项 | `head_turn`、`head_tilt`、`chest_lean`，目标为 `owner` |
| 人与玩具之间换视线，共 1 项 | `gaze_exchange`，目标为 `ball` |
| 自主微动作，共 8 项 | `ear_perk`、`ear_flick`、`air_sniff`、`soft_shake`、`body_shake`、`groom_paw`、`check_behind`、`nose_to_floor`，目标均为 `none` |

例如，严重饥饿、口渴或疲劳会限制转圈、邀玩、取物和跑动，轻柔姿态与休息仍可按各自条件开放。目录和执行前复查共用规则。[动作目录源码](../Assets/wjy_workspace/Dog1/DogCommandCatalog.cs)

## 返回

自然回应和控制计划使用独立字段。

```json
{
  "reply": "好呀，我就在这里趴下歇会儿。",
  "decision": "act",
  "reason": "",
  "actions": [
    { "id": "rest", "target": "none" }
  ]
}
```

| 字段 | 用途 |
| --- | --- |
| `reply` | 面向玩家的简短自然语言，可以和动作同时返回 |
| `decision` | `act` 提出动作计划，`decline` 说明当前无法或不愿执行，`reply` 进行交流 |
| `reason` | 模型对本轮判断的简短原因 |
| `actions` | `act` 选择一至三个有序动作，`decline` 和 `reply` 返回空数组 |
| `learningCondition`（可选） | 省略或 `none` 表示不创建条件教学；明确教授“以后我难过时做某个动作”时可用 `owner_sad`，只允许绑定一个可学习的基础动作 |

条件教学仍需真实动作完成并获得玩家表扬，才保存到长期记忆。当前表达难过不等于正在教授规则。模型输入也包含最近八条双向交流事件，每条最多一百字，作为当前会话上下文；临时对话不保存为长期记忆。

模型回应可以表达“我有点饿，先吃点东西再玩”，也可以给动作一句简短回应。动作是否真正完成由 Unity 的执行结果确认。旧协议的 `ready + chat` 可保留文字并停止动作，当前协议直接用独立的 `reply` 与 `actions` 表达两项职责。

## 校验与执行

接收端检查 JSON 字段、决策、动作数量、ID、目标及本次目录中的可用状态。一次计划最多含一次取物。整组计划先通过校验，随后每一步开始前再测量当前状态。目标被拿走或空间变化时，后续动作会停止。

有效自然回应在动作计划校验失败时保留，同时在调试记录中给出具体原因。自由语言输入已经关闭关键词动作匹配和模型失败后的本地动作兜底。模型没有返回有效结果时，这轮口令保持空动作。练习口令按钮等显式训练控件仍可调用本地训练逻辑，熟练度和奖励继续由游戏管理。

「说话 → DeepSeek 调试」显示输入、请求状态、原始模型返回、采用的决策来源及逐步执行结果。「打开本机语音记录」可查看逐轮转写，失败、无语音和取消也有记录。[接收与执行源码](../Assets/wjy_workspace/Dog1/Dog1Controller.cs) · [模型协议源码](../Assets/wjy_workspace/Dog1/DogLanguageModel.cs)

## 等待队列

完成休息、取球和练习后，执行端会同步相应生活状态与任务记录。休息目标 `none`、`house`、`cushion` 和成功的趴下姿态共用休息结果；成功取回球也记录陪玩。动作预览仅演示，不推进任务或奖励。行为完成与奖励冷却分别记录，失败或取消不能领取完成奖励。

新口令与动作计划的未开始步骤共享 **3 个待执行槽位**。新口令按后进先出处理，已经开始的动作先做完。同一条明确动作串保持原顺序。

排队口令入队时确定 5 秒截止时间，取出、重排和模型返回都不会续期。动作计划也受其等待窗口和原口令截止时间约束。超时取消尚未开始的步骤。队列满时会移除更早的待处理口令，已被计划占满的槽位会使新口令无法入队。调试界面显示等待项与剩余时间。[队列源码](../Assets/wjy_workspace/Dog1/Dog1CommandQueue.cs)

## 回归与真实模型联调

2026-11-26 前次使用本机 Whisper 和真实 DeepSeek，以下六例均通过协议联调。

| 测试 | 实际结果 |
| --- | --- |
| 固定中文 WAV「麦粒，坐下」 | 转写先保存，再返回 `sit` |
| 「休息会儿吧」 | 返回 `rest` 和自然回应 |
| 抬鼻闻空气的自然表达 | 返回微动作 `air_sniff` |
| 先坐下、抬右爪、再伏身邀玩 | 按顺序返回 `sit → paw → bow` |
| 要求叼来目录外的碗 | 返回自然拒绝，动作数组为空 |
| 严重饥饿时再次要求取球 | 根据不可用目录返回自然拒绝，动作数组为空 |

上述真实模型测试覆盖了转写、落盘、模型输出和后端解析。本次体验走查另完成真实 DeepSeek 七例测试，确认模糊休息、原地／狗屋／软垫目标、旧邀玩口令、明确条件教学与当前心情表达均可区分；[查看结果及测试范围](qa/dog1-experience-audit.md)。动作执行、非法计划、场景变化和队列边界另由 Unity 回归场景验证。真实语音部分使用固定合成 WAV，真人口音、室内噪声、实体 Quest 麦克风和头显交互仍需设备实测。
